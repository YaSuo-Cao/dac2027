# 已授权执行：RTL 反馈闭环，代码调用预算 B=5

2026-11-12 用户明确授权启动。本协议取代此前讨论稿中的“尚未启动”状态，但不改写历史 Fast/Full 定义。

- 母体固定为 168 题 × 5 HCL = 840；主模型 deepseek-v4.1-flash，确定性参数与原实验一致。初始生成复用冻结的 Gen 候选。
- 每个实例最多初始生成一次、代码修复四次。契约提取及其最多两次格式纠正另外计账，完整列出含契约的平均全部调用次数，不把 B=5 解释为含支持调用的总上限。
- 两个配对方法：NativeOnly-B5 在原生成功后停止；RTL-Aware-B5 在原生和 RTL 均通过后停止。原生成功前提示构建与历史规则一致，两方法完全相同的请求共用物理响应。
- C0 失败提供构造异常走 FL；原生失败沿用公开 clk/规格路由 FTL/FCL/FCTL。原生成功、RTL 失败则加入 RTL-L 分支，提供候选降级/RTL 验证的实际异常消息及冻结 L_l，要求保留原生行为及接口。
- RTL 提示只读取 JUnit failure/error 的 message 属性，记录来源与哈希；不读取测试源码、参考 Verilog，不提供 traceback 中测试代码。诊断过长时遵守预先固定的最多三条、每条 12000 字符上限并标记截断。
- 每轮重新经过 C0、官方 Q_native、C_RTL，同一评测指纹不变。候选替换仍只看 C0，不按 Q_native/RTL 在多个候选中择优；成功验收是停止条件。最新拒绝候选作为下轮反馈目标，保留最近通过 C0 的前驱作回退。
- 第二次及以后修复附上此前尝试的阶段、结果及源码哈希，要求避免重复失败实现。重复完全相同请求时停止，不把缓存命中算独立迭代；重复源码仍可继续至预算上限。
- 固定输出预算内的截断与格式错误消耗一次修复机会。传输/容器异常不算新的语义轮次，按原请求隔离重试，保留未知账单和重试证据；未解决工程故障阻断发布。
- 单独输出每轮 B=1..5、各语言 /168、总体 /840、原生与 RTL 成功率、逐轮新增恢复、代码及全部调用、输入/输出/缓存、五语言共享与单语言按需契约 Token、评测检查次数和记录耗时。
- 对照冻结 Direct/Gen Pass@5、G(P)-Gated Best-of-5 以及原两轮 Full。Pass@5 是 oracle any-pass，闭环使用实际功能/RTL反馈；信息条件和评测成本不同。B=5 为同代码调用上限，不声称同 Token 或同采样温度。
